## Proposed isolation

- New container `transmission-brother`, separate username/password via **untracked** `/docker/privacy/transmission-brother/auth.env` (mode 0600, fields `USER` and `PASS`).
- Dedicated config `/docker/privacy/transmission-brother/data:/config` and watch folder `/docker/privacy/transmission-brother/watch:/watch`.
- Narrow download mount `/srv/mergerfs/data/root/downloads/transmission-brother:/downloads`; the original downloads, Movies, and Shows are **not** mounted into the second container.
- Preseed `/docker/privacy/transmission-brother/data/settings.json` **before first start** with `"rpc-port":9092`, `"download-dir":"/downloads/complete"`, `"incomplete-dir":"/downloads/incomplete"`, `"incomplete-dir-enabled":true`, `"peer-port-random-on-start":false`, and `"peer-port":<distinct assigned port>`. Do not copy existing credentials/settings. LinuxServer documents that `USER` and `PASS` must be provided via environment and warns not to edit `settings.json` while running.
- Distinct AirVPN-forwarded torrent peer port `TRANSMISSION_BROTHER_PEER_PORT`, never 25045. Add this port alongside 25045 in live Gluetun's `FIREWALL_VPN_INPUT_PORTS`; add RPC **9092** alongside existing values to `FIREWALL_INPUT_PORTS`. Do not expose 9092 directly on the host.
- New `tailscale-transmission-brother` sidecar serves HTTPS to `http://gluetun:9092`. It has separate Tailscale state, a one-time local secret authkey file under the ignored `/docker/privacy/ts/` directory, and no Funnel. Restrict access in Tailscale policy to the brother's user/device. Shared Gluetun routing does **not** guarantee filesystem quotas or VPN port-forward allocation.

### TRAWL-only migration helper

The preflight normalizes `shm_size` from either Compose's human-readable `1gb` representation or an integer byte count. Any mismatch now identifies the exact Compose field instead of a combined message, and CI verifies the accepted/rejected size encodings. The earlier `TRAWL Compose service does not match reviewed runtime` failure occurred **before any container changes**; its precise mismatching field was not established from the first diagnostic output.

**2026-10-29 migration attempt:** The corrected preflight passed and the operator removed world-write from `/docker/privacy` and `compose.override.yml` (2775/664). First `--apply` failed at **new TRAWL /health**, and its rollback immediately reported the original `/health` unavailable. The previous helper performed a **single immediate health request** after container start for both creation and recovery. That is inadequate for browser startup. The migration now waits up to 90 seconds for the same container to become ready and rechecks runtime identity/status each time. **Do not retry until a fresh read-only probe confirms whether the restored original TRAWL is running and its `/health` responds.** A passing preflight, prior GitHub tests, or a successful Docker `start` alone is not proof of application recovery. Retain the root-only migration backup and inspect any remaining rollback container before another attempt.


The checked-in [`migrate_trawl.py`](migrate_trawl.py) provides a **read-only** `--check` and a guarded `--apply` for moving standalone TRAWL to the existing `privacy` Compose project, without touching Gluetun or Transmission. Use it only with the exact [`compose.trawl.yml`](compose.trawl.yml) from the same reviewed commit. It checks live Gluetun ID and health, image/default startup commands, TRAWL ports/mounts/env/shm/restart policy, Compose provenance, **unchanged effective configs for every existing service**, and TRAWL's local health response. Any mismatch stops before modifying services.

The helper will **refuse `--apply` while `/docker/privacy` or the live `compose.override.yml` is world-writable**. The October 29 host has both issues. Before a migration, inspect `getfacl -cp /docker/privacy /docker/privacy/compose.override.yml`; preserve the current owner and group, ACL entries, setgid bit and other service access. Removing *only* world-write with `chmod o-w` on these two verified paths may be appropriate after inspecting their management/permissions. Do not apply recursive chmod/chown or remove ACLs.

For a supervised migration, stage the helper and overlay together in a root-only directory, run `python3 migrate_trawl.py --check`, inspect PASS and permission warnings, then separately invoke `python3 migrate_trawl.py --apply`. The helper installs the overlay at `/docker/privacy/compose.trawl.yml` only if no conflicting overlay exists, stores the original container inspection in root-private `/root/awtserver-trawl-migration/`, stops/renames **only** standalone TRAWL, and uses `docker compose -f compose.yml -f compose.override.yml -f compose.amutorrent.yml -f compose.trawl.yml up -d --no-deps --no-build --pull never trawl`. It tests the new current-namespace Compose container and local `/health`. On failure it attempts TRAWL-only rollback; it keeps the stopped original container under a timestamped name after success for manual recovery. Never remove that backup before independently verifying Prowlarr's TRAWL integration. **Important:** the stopped original backup still has a Gluetun namespace reference, so the fail-closed Watchtower dependency checker will reject it as an unselected namespace child. After TRAWL and Prowlarr are verified, deliberately remove **only that verified stopped backup container** using its exact printed name (`docker rm <verified-backup-name>`), retain the root-only inspection backup, and recheck namespace consumers before any 30-target Watchtower enrollment.

The old Watchtower 24-target verifier will **still fail** after a TRAWL-only migration because additional VPN namespace users remain unselected. This is expected; enroll the reviewed full 30-target group only after the second Transmission and Tailscale sidecar exist and tests pass. Do not describe the migration itself as fixing Watchtower enrollment.

## Rollback

Keep dated copies of live Compose files, private Watchtower config/manifest, and new Transmission config. A rollback must **only** remove the two new containers and their new Compose overlay, restore Gluetun firewall policy and Watchtower selection with the complete namespace group accounted for, and leave all torrents and the original Transmission's files unchanged. Never run `docker compose down`, `down -v`, recursive `chmod`/`chown`, or delete persistent torrent/download data. Production application and VPN restarts require separate explicit host validation; this repository does not deploy them.
